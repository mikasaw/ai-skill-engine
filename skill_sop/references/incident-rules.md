# 事故纪律速查（串台 / 污染 / 历史改写）

## 串台（agent 交付与单据范围不符）

真实案例：agent 在单据正确（#2 收口）的情况下交付了完全无关的 726 行工具并提交进 main。

处置五步（验收方执行，前三步在判 0 分之前完成）：

1. **范围检查**：`git show --stat HEAD` 对照单据——不符即停止正常验收，进入事故模式；
2. **取证四件套**（先取证再定论，不动 main）：
   - 单据是否被篡改：`issue get <id>` 核对 description 原文；
   - run 归属：`issue runs <id>` 看 `attribution`（agent_id / evidence.kind / initiator）；
   - 时间对齐：污染 commit 时间 vs run completed；
   - 引用物核实：交付报告引用的关联单号在工作区是否存在；
3. **判 0 分不通过**：verdict reasons 固化全部证据，处置要求写明"污染 commit 需项目主拍板"；
4. **处置**（项目主拍板）：A = `git revert <污染commit>`（推荐）；B = 先移存内容再 revert；
   `reset --hard` 丢审计痕迹，anti-pattern；
5. **重派**：打回指引评论先在案 → `issue rerun <id>`（自动取消在途 run）→
   重跑验收加一条**范围一致性复查**。

## 净零例外与历史改写禁令

- 事故提交对（污染 + revert）**永久保留在 git log**：它们是审计痕迹；
- 放行标准：`git diff <事故前> <revert后>` 为空，可用**树对象同一**
  （`git cat-file -p <前>^{tree}` 对比）加强；
- 任何人（含 Architect、含外层验收）提议 reset/rebase/amend 抹痕迹 = **BLOCKER**，停手回报。

## 防御代码红线

- **不可达防御 = MAJOR**：给某分支加守卫前，先证明该分支独立可达
  （例：读侧先抛异常 ⇒ 写侧守卫正常走不到，加了就是死代码）；
- "真失败裸 errno 未转译"若属父单已裁范围外，是**正确取舍**不是缺口——
  留档即可，将来要加守卫必须先给出该分支可达的证据。

## 递归删除红线

- `shutil.rmtree` / 任何递归删除目录的操作**绝对禁止**——
  key/路径参与拼装时，递归删除 = 路径穿越越权删除的同类放大（真实案例：`../../VICTIM`）；
  清理失败最多留下无害孤儿，"缓存记账与磁盘状态解耦"。
