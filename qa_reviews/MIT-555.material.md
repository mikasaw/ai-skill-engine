### 数据契约

```python
class FrontMatterError(Exception): ...      # 所有格式错误都抛它，消息必须带原因

@dataclass(frozen=True)
class Task:
    source: str      # 源文件路径，str(path)
    title: str
    status: str      # 归一化后只会是 "todo" / "doing" / "done"
    tags: list[str]

def parse_file(path: str | Path) -> Task | None
def parse_dir(path: str | Path) -> list[Task]
```

### 本阶段裁决（已定，不再讨论）

1. front-matter 判定：文件**首行**（去掉 UTF-8 BOM、右侧空白）必须恰为 `---`；否则视为格式错误。
2. 无 front-matter（首行非 `---` 且文件非空）→ 抛 `FrontMatterError`，原因含 `missing front-matter fence`。
3. 有开栏但闭栏 `---` 缺失 → 抛 `FrontMatterError`（`unterminated front-matter`）。
4. 空文件（0 字节）→ 抛 `FrontMatterError`（`empty file`）。
5. 非 `.md` / `.markdown` 后缀 → `parse_file` 返回 `None`，`parse_dir` 静默跳过，绝不抛异常。
6. 未知字段（如 `assignee: bob`）→ 忽略，不报错。
7. 缺省规则：`status` 缺失或值为空 → `"todo"`；`title` 缺失或为空 → 文件名 stem；`tags` 缺失 → `[]`。
8. `status` 非法值（不属于 todo/doing/done）→ 抛 `FrontMatterError`，消息必须同时含文件路径与非法值原文。大小写与前后空白先归一化（`Doing` → `doing` 合法）。
9. `tags` 接受两种写法并都归一化为 `list[str]`（元素 `strip()`、丢空）：`tags: 前端, 紧急` 与 `tags: [前端, 紧急]`。
10. `title` / `status` 值两侧成对引号（单或双）脱掉；字段行内 `#` 后缀注释不剥离。
11. 解析必须**先归一化换行**（CRLF / CR → LF）再逐行，Windows 下读文件用 `encoding="utf-8-sig"`，保证 LF 与 CRLF 测试样例结果一致。
