### 数据契约

```python
@dataclass(frozen=True)
class TaskMeta:
    mtime: float
    size: int

@dataclass
class RebuildReport:
    parsed: list[str]      # 本次真正走 parse_file 的源文件（posix key）
    reused: list[str]      # 命中快照、未解析的源文件
    changed: list[str]     # 渲染产物字节发生变化的源文件（含新增）
    removed: list[str]     # 源文件已消失，卡片产物与状态条目被清掉
    rebuilt_page: bool     # index.html 是否被重写

def load_state(cache_file: str | Path) -> dict[str, TaskMeta]      # 不存在则返回 {}
def save_state(cache_file: str | Path, state: dict[str, TaskMeta]) -> None
def build(tasks_dir: str | Path, out_dir: str | Path) -> RebuildReport
```

### 落盘布局（S3 新增，路径固定）

```
build/index.html            # 由卡片片段拼装，不重新 render_card
build/cards/<key>.html      # 单任务卡片片段，key = sha1(posix_source.encode()).hexdigest()[:16]
build/state.json            # {"key": {"source": posix路径, "mtime": float, "size": int, "status": str}}
```

`state.json` 里保留 `source` 与 `status`，因为零重解析运行时整页仍需要知道列归属和标题来源——**从 state.json 读，不再解析 .md**。

### 本阶段裁决

1. 复用判定发生在**解析之前**：先 `stat` 比对 mtime+size，命中即视为未变更，绝不打开文件解析。零重解析的可观测证据就是 `report.parsed == []`。
2. 变更判定用 **mtime + size 两项**（与父 issue 一致）。同秒内改写且 size 不变无法察觉——这是**已接受的限制**，**不要**引入内容哈希。测试制造变更时用"追加文本使 size 变化"。
3. 无变更二次运行：`parsed == []`、`changed == []`、`rebuilt_page is False`，且 `build/index.html` 与 `build/cards/*.html` 的 mtime 不前进（不重写即不动）。
4. 单文件变更：`parsed == [该文件]`、`changed == [该文件]`；其余 `build/cards/*.html` 文件**字节与修改前完全相同**（测试逐个读回比对），`rebuilt_page is True`。
5. 整页每次 `rebuilt_page` 为 True 时全量重写（拼装成本极低），但"自身渲染产物"的粒度是卡片片段——验收看第 4 条的逐卡片字节比对，不看整页 diff。
6. `build()` 必须能在 `out_dir` / `build/cards/` 不存在时创建；`state.json` 写入用先写临时文件再替换，损坏的 `state.json` 视为空快照（全量重建），不抛异常。
7. `cli.py`：`python -m mdboard.cli <tasks_dir> <out_dir>`，打印一行人类可读报告（parsed/reused/changed/removed 计数），退出码 0；解析失败（`FrontMatterError`）→ 打到 stderr，退出码 1，**不得**吞掉异常原因。

## 架构师补充裁决 #2（Stage 2 关闭时下发）

### 1. S1 引号剥离契约已正式扩围（不是 dev 越权）

S1 原裁决第 10 条只写了 `title` / `status` 两侧成对引号脱掉，没覆盖 flow-style 列表项。S2 期间真实工件暴露：`tags: ["x&y"]` 解析为 `['"x&y"']`，渲染出用户可见的 `&quot;`。自动质检要求修复，dev 已改 `frontmatter.py` 的 `_read_tags`（逐项走与 title/status 同一个 `_unquote`），并补 7 条回归用例，提交 `343d34b stage1: strip paired quotes per flow-style tag item (regression surfaced by S2)`。

**追认该修复为契约变更**：成对引号剥离适用于 title、status 以及 flow-style tags 的每一项。**S3 不需为此改任何东西**（卡片片段里存的是转义后文本，S3 不重新推导 tags）——写在这里是为了让 S3 知道 51+27=78 这条基线是当前状态，而不是"S1 用例会变少"。

### 2. 快照不感知"渲染器/解析器自身升级" —— 已接受，不要加版本键

mtime+size 快照只感知**源文件**变化。若有人只改 `render.py` 而不碰 .md，缓存片段不会失效。这是**已接受的限制**，与裁决 #2（同秒改写看不见）同一类。

**明确禁止**为此在 `state.json` 里加 `version` / `renderer_hash` / `schema` 之类的键，也禁止顺手引入内容哈希——它会连带把"零重解析"的判据复杂化。需要清缓存的手段已经存在且足够：删掉 `build/` 目录即全量重建。S3 的测试里请带上"删 `build/state.json` 后下一次运行 `parsed` 覆盖全部文件"这一条，把这条逃生通道钉住。

### 3. S3 依赖的 S2 事实（已核实）

`mdboard/render.py` 已交付 `render_card` / `render_page` / `write_page`；`render_card` 返回 `<article class="card">` + `<h3>` + `<ul class="tags">` 的纯片段（不含整页内容），正是本 issue 要缓存的"自身渲染产物"；列内顺序由 `render_page` 按 `source.replace("\\", "/")` 字典序保证，同输入两次渲染逐字节相等——本 issue 的逐卡片字节比对依赖这点，成立。`.gitignore` 仍由 S3 负责追加 `build/`。
